# Import recovery adapter interface

`rewindsafe.import_recovery` implements the shared `WorkflowAdapter` contract. The API imports/registers it at startup; `agent.start_run` selects it from the grant's `workflow` field, and every tool call enters `runtime.dispatch.dispatch` unchanged.

## Input contract

An import has three separate row sets: `current_records` (current application state), `snapshot_records` (approved restore source), and `authority_records` (protected facts). The caller supplies the source primary-key column, tenant column, repairable fields, destination-to-source column mapping, and mandatory `approved_snapshot_digest`. The digest is canonical SHA-256 over the complete raw `snapshot_records` only. The API requires every row to have a key and tenant, exact key coverage across the three sets, unchanged tenant ownership, unique keys, and all four supported authority facts (`tombstoned`, `revoked`, `held`, `later_edit`). `authority_mapping` maps each canonical fact to its source column; omission keeps the legacy same-name mapping. `authority_columns` must list all four flag source columns and may list additional protected metadata columns. Undeclared authority columns are rejected. Key, tenant, authority-only, and repairable columns must be disjoint.

Repairable fields are user-selected simple canonical names mapped to source columns, with one declared scalar type per field: `string`, `integer`, `number`, or `boolean` (nullable values are allowed). Source headers may contain spaces or Unicode, but must be unique, nonempty, bounded, and free of control characters. Only flat scalar values are supported; objects, arrays, non-finite numbers, unsupported names and undeclared authority columns fail closed. Missing types are inferred only for legacy `quantity` and `location` sample packs. The current-row table keeps record key, tenant and other identity data in separate columns; its `repair_values` JSONB contains exactly the dataset-catalog fields. Every unmapped current and snapshot source column is retained in `source_metadata` as immutable provenance, never as a repair candidate. Extra authority columns are retained in the immutable authority `detail` object. Metadata is limited to 100 columns and bounded scalar values; nested event ledgers are rejected. Imported values never become SQL identifiers or statements. Data is limited to 500 rows and 2 MB per CSV/JSON input. CSV uses unique headers; JSON is an array of row objects.

The database role can update the `repair_values` container plus row version and audit metadata. PostgreSQL column privileges restrict that container column; the dataset field catalog and runtime enforce which JSON keys and fields a specific grant may change. The `source_metadata` column is excluded from executor update privileges. PostgreSQL does not individually restrict keys inside JSONB. The authenticated `POST /api/imports/postgres-preview` route can read three selected source tables in a read-only transaction, retaining every current/snapshot source column and the explicitly selected authority columns. It requires an administrator-configured exact host allowlist, TLS `verify-full`, DNS pinning, quoted identifiers, at most 100 columns, 500 rows, 2 MB per table, and short connection/statement/transaction timeouts. Snapshot inspection returns only record key, tenant, and approved repair values; arbitrary source metadata stays out of planner context. The DSN is transient input, never stored or echoed. The local CLI source path reads its DSN only from a named environment variable. Neither path accepts SQL or writes to the source connection.

## Workflow and authority

The five registered tool names match the existing scripted recovery planner: `inspect_snapshot`, `compare_current`, `prepare_repair_manifest`, `apply_repair_manifest`, and `get_recovery_receipt`. Grants bind one tenant, selected record IDs, exact repair fields, dataset ID, snapshot ID, and snapshot digest. Manifest preparation resolves new values only from the digest-verified snapshot table. Apply rechecks grant state, catalog membership, snapshot values/digest, current tenant, row versions, global and imported tombstones, active and imported holds, imported revocation and later-edit flags, and linked access-grant revocation inside one transaction. A row edited after import becomes protected after its baseline version; an edit between manifest preparation and apply makes the manifest stale. Imported authority records stay scoped to the dataset and never overwrite global authority tables. Idempotency is unique per grant and key.

## API / CLI

- `GET /api/imports/samples` lists the three bundled sample packs.
- `GET /api/imports/samples/{sample_id}` reads the pack inputs and mappings.
- `POST /api/imports/preview` validates and imports supplied CSV/JSON text, returning dataset ID and comparisons.
- `POST /api/imports/postgres-preview` imports three allowlisted PostgreSQL tables using a transient DSN and the same validation/runtime path.
- `POST /api/imports/samples/{sample_id}/import` imports a bundled pack.
- `POST /api/imports/grants` creates a normal DRAFT TaskGrant; standard authorize and run routes continue the workflow.
- `python -m rewindsafe.imports_cli samples`, `import-sample ID`, and `run-sample ID` list, stage, or run a sample through the common dispatcher. `import-postgres` is the bounded, read-only source-table import path.

The digest proves input integrity and binds the preview to the exact source. It is not a cryptographic signature or proof that an external party approved the snapshot; the approval record and digest must come from the caller's trusted snapshot process.
