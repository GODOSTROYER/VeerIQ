# Read-only PostgreSQL imports over TLS

The import endpoint reads current rows, approved snapshot rows, and authority rows from three operator-selected PostgreSQL base tables. It copies only validated rows into RewindSafe; the source session uses a read-only transaction and the source role should have `CONNECT`, schema `USAGE`, and `SELECT` on only those three tables.

Configure the API service with `REWINDSAFE_IMPORT_POSTGRES_ALLOWED_HOSTS` as a comma-separated list of exact DNS hostnames. The default is empty, which disables PostgreSQL imports. Do not use wildcard entries. The connection must use `sslmode=verify-full`; the service validates the requested hostname against the certificate and pins a resolved address for that connection. Put the trusted CA certificate in the API service's normal libpq trust configuration or set `PGSSLROOTCERT` in that service environment. The request cannot supply a CA path or override TLS settings.

The DSN is transient request input. The API accepts only host, port, database, user, password, SSL mode, and application name parameters. It rejects service files, alternate host addresses, unsupported libpq options, non-allowlisted hosts, system schemas, and non-base tables. It quotes schema/table/column identifiers, reads at most 500 rows per table, and uses short connect, statement, and idle transaction timeouts. The endpoint never accepts SQL and does not write to the source. Source credentials should belong to a dedicated read-only role and must not be placed in logs or persistent import metadata.

The mapping and approval contract is the same as CSV/JSON imports: `primary_key`, `tenant_column`, typed `repairable_columns`, `authority_columns`, destination-to-source `column_mapping`, and a mandatory `approved_snapshot_digest` over the exact approved snapshot records. The digest must be computed by the trusted snapshot approval process. All three tables must include the complete mapped row set, and authority facts remain scoped to the imported dataset.

The positive integration check `test_tls_postgres_source_import_runs_and_leaves_source_unchanged` runs when `REWINDSAFE_TEST_IMPORT_SOURCE_PASSWORD` and `PGSSLROOTCERT` point to a disposable TLS source. It imports through the API route, authorizes and runs the standard scripted workflow through the common dispatcher, verifies an eligible row is repaired while a held row is preserved, confirms a source write is rejected by PostgreSQL, and rereads all source tables to verify their contents are unchanged. It skips when those two test inputs are absent.
